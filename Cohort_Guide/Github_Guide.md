# 🐙 GitHub Guide for Data Analytics Learning

## 🎯 Purpose

GitHub will be used as the official portfolio management platform for this learning journey.

Each member is expected to maintain a personal GitHub repository that documents:
- daily learning progress
- datasets
- manual practice
- completed analysis files
- insights
- reflections
- screenshots
- project documentation

The goal is not just to upload files.

The goal is to build a professional analytics portfolio.

---

# 📌 Why GitHub Matters For Data Analysts

GitHub helps analysts demonstrate:

- organization
- documentation skills
- project structure
- consistency
- technical growth
- communication ability
- portfolio discipline

A good GitHub portfolio helps others understand:
> what you learned, how you solved problems, and what insights you extracted.

# 📂 Recommended Day Folder Structure

Each daily topic should have its own folder.

Example:

```text
Day_11_Advanced_Correlation_Analysis/
│
├── Raw_File/
├── Completed_Analysis/
├── Manual_Practice/
├── Screenshots/
├── Insights/
└── README.md
```

---

# 📦 What Each Folder Should Contain

## 📄 Raw_File

This folder should contain the original dataset before solving.

Example:

```text
Day_11_Dataset.xlsx
```

---

## ✅ Completed_Analysis

This folder should contain the completed Excel workbook after formulas, charts, and analysis have been done.

Example:

```text
Day_11_Completed_Analysis.xlsx
```

---

## 🧮 Manual_Practice

This folder should contain manual calculations, handwritten notes, typed steps, or formula workings.

Example:

```text
Day_11_Manual_Practice.pdf
Day_11_Manual_Practice.md
```

---

## 🖼️ Screenshots

This folder should contain screenshots of:
- charts
- formulas
- pivot tables
- dashboards
- key outputs

---

## 💡 Insights

This folder should contain written insight summaries.

Example:

```text
Day_11_Insights.md
```

---

## 📝 README.md

This file explains the day’s work clearly.

It should include:
- objective
- dataset description
- concepts learned
- formulas used
- analysis process
- insights
- challenges
- outcome

---

# 🔁 GitHub Workflow

For each day:

1. Create the day folder
2. Add the raw dataset
3. Complete the analysis
4. Add the completed workbook
5. Add manual practice
6. Add screenshots
7. Write the README.md
8. Commit changes
9. Push to GitHub

---

# 📌 Repository Rules

Each member must:

- use clear folder names
- avoid random file names
- keep work organized
- update README files consistently
- upload both raw and completed files
- document insights properly
- avoid deleting previous work
- maintain weekly reflections

# 📝 README Quality Standard

A strong README should make the work understandable even to someone who did not attend the lesson.

It should answer:

- What was the topic?
- What was the objective?
- What dataset was used?
- What formulas or tools were applied?
- What results were found?
- What insights were extracted?
- What challenges were faced?
- What was learned?

---

# 📘 Weekly Reflection Standard

At the end of every week, each member should write a reflection covering:

- topics covered
- concepts learned
- challenges faced
- how challenges were solved
- strongest insight
- portfolio progress
- areas for improvement
- next week goals

---

You can also add a study note to your everyday learning, and extract your full day's learning from AI as a Study_Note.md, or compute it manually as the class progresses and type it in a README.md format. Note that this is optional.
